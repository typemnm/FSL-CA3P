# Mac mini 배포 알림 보드

대시보드의 **배포 알림**에서 develop 병합 이후의 CI와 실제 Mac mini 적용 상태를 확인한다. 상단 종 아이콘에는 읽지 않은 배포 알림 개수가 표시되며, 보드를 열면 읽음 처리한다. 알림은 이 대시보드 안에서 표시하며 이메일·메신저·운영체제 알림 권한은 사용하지 않는다.

## 확인할 수 있는 정보

- 실제 HTTP 프로세스의 실행 SHA와 최근 관측한 develop 대상 SHA
- 같은 SHA의 CI 대기·진행·실패·전체 검증 통과와 Actions 링크
- 장치의 CI 대기, 의존성·격리 점검·대학 이미지 준비, 기존 검사 종료 대기, 버전 전환, 적용 완료
- 배포 실패·이전 버전 복원 완료·운영자 복구 필요 상태
- 마지막 장치 확인·최근 적용·CI 수집 시각과 GitHub API 한도에 따른 재시도 시각
- 읽지 않은 알림과 최근 최대 100개 단계 변화 이력

CI가 성공해도 장치가 새 버전을 실행한다고 표시하지 않는다. 현재 실행 SHA는 대시보드 프로세스에서 확인하고, 장치가 보고한 대상 및 같은 SHA의 CI를 따로 표시한다. 더 최신 develop의 CI가 시작되면 장치가 아직 확인하지 못했더라도 새 대상의 CI 진행을 보여준다. 실제 target 확인 시각이 없는 값은 미확인으로 표시한다.

대시보드는 로그인 후 20초마다 읽기 전용 `/api/operations`를 조회한다. 숨긴 탭·로그아웃 중에는 중단하고 복귀 시 다시 조회한다. 네트워크 오류가 나면 마지막 자료를 유지하되 현재 완료로 확정하지 않는다. 상태 갱신이 10분 넘게 없거나 CI 실시간 조회가 불가능하면 오래된/미확인 자료임을 표시한다. 이것만으로 장치가 꺼졌다고 단정하지 않는다.

Mac updater의 확인 주기는 기존 120초, 서버의 CI 수집은 기존 기본 5분이다. 20초 화면 갱신이 GitHub나 장치 상태를 20초 이내에 반드시 감지한다는 뜻은 아니다. CI 수집은 공개 요약 피드 외에 최신 develop push 실행 목록을 주기당 1회 확인한다. 새 run 또는 재실행은 이전 성공과 별개로 표시하며, 실제 suite 개수·필수 게이트가 확인되기 전에는 통합 검증 통과로 표시하지 않는다. API 한도에 도달하면 기다리고 이전 결과를 보존한다.

## 설치와 기존 updater 호환

대시보드 변경은 해당 PR 병합·전체 CI 성공·기존 Mac updater의 적용 후 보인다. 이 보드가 배포를 시작하거나 중단하지는 않는다. 조회 계정도 볼 수 있으며 기존 로그인/권한·동일 원점 보호를 사용한다.

기존 updater도 현재 `status.json`은 제공하므로 보드의 현재 상태를 볼 수 있다. **과거 단계 이력을 쌓으려면 안정 경로에 있는 controller를 한 번 다시 설치해야 한다.** updater는 릴리스와 별도로 보관되므로 develop의 새 dashboard 코드만 적용해서 controller 파일까지 바뀌지는 않는다. 새 installer는 `device-deploy-events.mjs`도 복사한다.

배포가 진행 중이 아닌지 확인한 다음, 검토된 새 소스 체크아웃에서 기존 설정 경로로 실행한다. 아래 경로는 기존 [장치 배포 안내](DEVICE_DEPLOYMENT.md)의 예시이며 장치 설정을 따른다.

```sh
CA3P_NODE=/Users/casper/dev/CA3P/FSL-CA3P/.runtime/bin/node
CA3P_DEPLOY_ROOT=/Users/casper/dev/CA3P/FSL-CA3P/.runtime/device-deploy
CA3P_DEPLOY_CONFIG="$CA3P_DEPLOY_ROOT/config.json"
"$CA3P_NODE" scripts/install-device-deploy.mjs --config "$CA3P_DEPLOY_CONFIG" --no-start
```

`--no-start`는 현재 dashboard를 재시작하거나 updater를 시작하지 않는다. 실행 중인 updater가 없는 상태에서 controller와 plist를 갱신하고, 이미 등록된 updater는 다음 정상 주기에 새 controller를 실행한다. 재등록이나 시작이 필요한 경우 [기존 설치 절차](DEVICE_DEPLOYMENT.md#설치)를 따른다. 진행 중인 배포를 강제 종료해 설치하지 않는다. 이번 변경을 개발하는 동안 실제 Mac 설정·프로세스·운영 데이터는 변경하지 않았다.

새 이력은 `deployRoot/status.json.events`에 현재 상태와 함께 atomic하게 저장된다. 같은 SHA의 checking/up-to-date 반복 확인은 이력과 알림을 늘리지 않는다. 상태·단계·대기 사유·재시도 시점·대상 SHA가 바뀐 의미 있는 전환만 남긴다. 이력이 없는 구 controller에는 현재 상태 하나를 표시하고 이력 설치 안내를 표시한다. 설치 이전에 지나간 단계는 복원하지 않는다.

## 보존과 진단

이력에는 상태·SHA·시각·Actions run 식별자·정해진 사유 코드만 저장한다. 원시 오류 문자열·파일 경로·API 키·계정·Docker 로그는 외부 API에 내보내지 않는다. UI의 설명은 정해진 코드에 대응하는 문구다. 자세한 실패 원인은 기존 장치의 비공개 배포 로그에서 확인한다.

배포 이력과 읽음 정보는 모델 실험 초기화와 분리한다. 실험 이력·보고서를 초기화해도 운영 상태 이력은 지우지 않는다. 읽음 ID는 해당 브라우저의 앱 전용 localStorage에만 보관된다. 다른 브라우저의 읽음 상태와 동기화하지 않으며, 연결이 없는 동안의 모든 중간 CI 단계 관측을 보장하지 않는다. 장치 전환 이력은 controller의 bounded journal로 이어진다.

실제 Mac이 로그아웃·절전·전원 종료 상태이거나 Docker/네트워크/패키지 저장소를 사용할 수 없으면 최신화가 늦어질 수 있다. 보드는 관측한 사실과 신선도를 보여 주며 배포 성공이나 복구를 대신 수행하지 않는다.
