# 전월 CERT 취약점 보고서 예시: 검색 입력 XSS

**이 문서는 팀이 설명한 상황을 재현한 가상 예시다. 실제 점검 보고서나 관찰 증거는 아직 받지 않았다.**

| 보고서 항목 | 전월 보고서의 예시 내용 |
|---|---|
| 보고일 | 2026-08-20 (예시) |
| 취약점 유형 | XSS, 반사형이라고 가정 |
| 발생 URL | `https://lab.example.invalid/search?q=sample` (존재하지 않는 예시 호스트) |
| 심각도 | medium (예시이며 실제 평가는 팀 보고서로 교체) |
| 상세 발생 방법 | `GET /search`의 `q`를 HTML 본문에 출력할 때 필요한 출력 인코딩이 누락된다고 가정. 실습 브라우저에서 시험 입력을 보내고, 문자열 반사가 아니라 브라우저 실행 결과를 확인한다. |
| 전월 증거 | 시나리오상 브라우저에 `casperProof` 표식이 설정된 것으로 가정. 실제 캡처나 기록은 아직 제공되지 않음. |
| 조치 방안 | 출력 문맥에 맞는 인코딩을 적용하고, 수정 후 같은 입력으로 재점검한다. |
| 현재 패치 상태 | unknown. 전월 발견과 이번 달 현재 상태는 다를 수 있음. |

이번 달 CERT에서 이 보고서를 DB로 불러오고, 엔드포인트 파서가 발견한 경로와
대조한다. 경로가 같으면 재점검 후보가 된다. 실제로 아직 취약한지는 이번 달
실행 결과로 확인한다.

DB 입력 파일은 `case.example.json`이다. 팀의 실제 모의 사이트와 보고서가 준비되면
URL, 심각도, 절차, 조치 방안, 전월 증거를 그 자료로 교체한다.
