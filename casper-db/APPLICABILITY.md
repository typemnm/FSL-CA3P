# 공개 권고와 대상 소프트웨어의 영향 범위 비교

공개 CVE가 있다는 사실, 대상 소프트웨어가 영향 범위에 포함된다는 사실, 실제 서비스에서 재현됐다는 사실을 구분한다. 내부 CERT 보고서와 외부 공개 권고는 서로 다른 원천이며 평가 과정에서 합치거나 수정하지 않는다.

## 입력과 결과

`casper-software-inventory-1`은 대상 ID·관찰 시각과 구성 요소별 생태계·패키지·버전·근거 참조를 받는다. 버전을 확인하지 못하면 비워 둔다. CPE와 호출 경로는 선택값이다. 호출 경로는 근거로 전달하며 코드가 실행됐다는 판정으로 사용하지 않는다.

| `decision` | 의미 |
|---|---|
| `affected_version` | 제공된 제품·버전·환경 조건이 공개 영향 범위에 일치함 |
| `outside_affected_scope` | 일치하는 제품의 버전 또는 명시적 환경 조건이 범위 밖임 |
| `needs_review` | 제품·버전·조건이 부족하거나 비교 문법을 지원하지 않음 |
| `withdrawn` | 원천 권고가 철회됨 |

모든 평가는 `reproduction_state=not_assessed`, `automatic_execution_allowed=false`를 유지한다. 목록에 제품이 없다는 것만으로 설치되지 않았거나 안전하다고 판단하지 않는다.

## 비교 기준

- GitHub Advisory: 생태계·패키지 이름과 `vulnerable_version_range`를 비교한다. pip 이름의 대소문자·구분자를 정규화한다.
- npm: 완전한 SemVer 버전과 비교 연산자를 지원한다. 사전 배포 버전은 명시적 사전 배포 비교 근거가 없으면 검토로 보낸다.
- Maven·pip·CPE: 숫자 릴리스 버전을 지원한다. 지원하지 않는 접미사·범위 문법은 추정하지 않는다.
- 범위: `>=`, `<=`, `>`, `<`, `=`, `==`, 쉼표 교집합, `||` 합집합, `*`, `[1.0,2.0)` 형태 구간을 지원한다. caret·tilde·일부 버전 wildcard 등은 `needs_review`다.
- NVD: CPE 2.3 제품 식별과 시작·끝 버전, AND/OR 환경 조건을 비교한다. 환경 조건 누락·부정 조건·해석 불가 CPE 패턴은 검토로 남긴다.

버전 비교기는 명시된 문법 안에서 판정하는 로컬 코드다. 패치 백포트·런타임 설정·실제 도달 가능성은 이 결과만으로 증명하지 않는다.

## 저장과 갱신

기본 평가에는 쓰기가 없다. `--apply`는 기존 외부 DB의 `external_assessments`에 원천 권고 해시·소프트웨어 목록 해시·관찰 시각·필드별 근거를 포함하는 스냅샷을 추가한다. 동일 입력은 중복 생성하지 않는다. 같은 대상·관찰 시각에 다른 목록을 저장하면 충돌로 거부한다.

`external_active_inventory`는 가장 최근 관찰 목록을 가리킨다. 과거 목록을 뒤늦게 등록해도 최신 목록을 덮어쓰지 않는다. 권고가 갱신되거나 새 목록이 활성화되면 이전 평가는 남겨 두고 조회의 `current=false`로 구분한다. 평가 중 원천이 바뀌면 저장을 거부한다.

`casper-reference-1.external.assessments`로 후속 모듈에 결과·근거·최신 여부를 전달하며 보고서 렌더러도 이를 표시한다. 실제 재현 결과는 검증기의 별도 Check와 증거를 사용한다.
