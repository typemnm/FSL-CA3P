# CA3P Agent Loop — 로컬 통합 대시보드

`DESIGN.md`의 검정 배경, 민트·제이드 별빛과 주변광을 적용한 로컬 대시보드입니다. **코어 fixture**, 기존 **단일 XSS/IDOR 검사**, 실제 DeepSeek 모델을 사용하는 **범용 점검**을 구분합니다. 세 실습 대상의 이름은 사이트를 가리키며 검사할 취약점 유형을 뜻하지 않습니다.

## 실행

대시보드 서버만 실행하려면 Node.js 24가 필요합니다. 기존 저장형 XSS 실습에는 PATH에서 실행할 수 있는 `curl`, `xss-parser`의 npm 의존성과 Playwright Chromium, Python 3.11 이상과 `casper-db`의 Pydantic 의존성이 필요합니다. 범용 점검은 `xss-parser`를 호출하지 않지만 실제 DeepSeek 설정이 필요합니다. 설치 명령은 [루트 README](../README.md)에 있습니다. 프로젝트 루트에서 실행합니다.

```powershell
npm start
```

또는 대시보드 디렉터리에서 직접 실행할 수 있습니다.

```powershell
cd agent-dashboard
npm run dev
```

브라우저에서 <http://127.0.0.1:4173>을 엽니다. 서버는 `127.0.0.1`에만 바인딩합니다. 터미널에서 `Ctrl+C`로 종료합니다. 루트 시작 명령에 `npm start -- --port 4174`를 사용하거나 대시보드에서 `$env:PORT = '4174'`를 설정한 뒤 실행하면 포트를 변경할 수 있습니다.

## 사용 방법

1. 고정 응답으로 화면과 코어를 확인하려면 URL을 입력하고 **코어 fixture 시작**을 누릅니다. 이 URL은 기록용이며 접속하지 않습니다.
2. 실제 범용 점검은 `agent/.env` 또는 프로세스 환경변수에 `DEEPSEEK_API_KEY`를 설정한 뒤 대상과 **범용 취약점 점검**, 사용 가능한 DeepSeek 모델을 선택해 시작합니다. 게시판은 서버가 임시 격리 인스턴스를 만들며, 대학 대상은 등록된 실습 원점을 입력합니다. 모델 API 호출은 과금될 수 있습니다.
3. 기존 재현 경로가 필요하면 **기존 단일 검사**를 선택합니다. 게시판은 저장형 XSS canary 1회, 두 대학은 알려진 레코드의 IDOR 읽기 비교만 수행합니다.
4. 실시간 진행 상태와 증거, 모델 호출 기록을 확인합니다. 중지를 누르면 진행 중인 요청에서 중단을 시도합니다. 실행 이력의 결과는 JSON으로 내보낼 수 있습니다.

범용 모델 요청의 기본 최대 출력은 2,048토큰입니다. `DEEPSEEK_MAX_TOKENS`를 명시하면 그 값을 우선 사용합니다.

범용 점검은 HTTP/인증 읽기 관측, 허용된 저장소 소스·의존성, 이전 실행 및 사례·카탈로그 요약을 출처와 함께 모델에 제공합니다. 모델은 유형을 미리 지정받지 않고 여러 가설을 제안하지만, 실행은 등록된 대상·경로·요청 예산으로 제한됩니다. 게시판에서는 실행별 격리 인스턴스의 새 합성 글에 한해 교차 사용자 삭제를 대조하고, 대학 대상에서는 알려진 레코드의 역할별 읽기를 비교할 수 있습니다. 확인 가능한 근거가 없는 가설은 `inconclusive` 또는 `not_tested`로 남깁니다. 보류 중인 `xss-parser`는 이 경로에 연결하지 않았으므로 브라우저 실행 증거가 필요한 XSS는 확정하지 않습니다. 범용 다중 결과는 실행 이력과 JSON에 저장하고, 최종 `confirmed` finding마다 HWPX 초안을 한 개씩 작성합니다. 다른 상태에는 HWPX를 작성하지 않습니다.

### 로컬 실측 기록

2026-10-26에 `127.0.0.1:4174`의 `vul-web-1` 격리 게시판에서 실제 DeepSeek Flash 범용 점검을 완료했습니다. 6회 반복, 22개 검사, 21개 가설 중 교차 사용자 삭제 1건을 독립 확인했고, 판정 불가 14건과 미점검 6건을 기록했습니다. 반복 예산(`iteration_budget`)에 도달해 종료됐으며 모델 호출 6회·총 38,716토큰이 기록됐습니다. 중앙 이력 재조회와 새로고침 후 보고서 복원을 확인했습니다.

이 실측에서는 Windows의 기본 `python.exe` 별칭이 실행되지 않아 `casper-db` 스냅샷이 `unavailable`로 기록됐습니다. 기존 사례 DB는 0건이므로 누락된 기존 사례는 없습니다. 사례 이력을 사용하려면 `CASPER_DB_PYTHON`에 `casper-db` 의존성이 설치된 정상 Python 실행 파일을 지정하세요. 사용할 수 없는 입력은 결과에 `unavailable`로 남깁니다.

같은 날 대한대학교 `4101` 범용 실행은 6회 반복·26개 가설·23개 검사로 완료됐습니다. `/api/admissions/partner/applications/:id`에서 접근 제어 1건을 독립 확인했고, 판정 불가 14건·미점검 11건을 기록했습니다. DeepSeek 호출은 6회, 총 64,087토큰입니다.

원창대학교 `4102` 범용 실행은 6회 반복·23개 가설·22개 검사로 완료됐습니다. `/api/staff/mobile/cases/:id`에서 접근 제어 1건을 독립 확인했고, 판정 불가 14건·미점검 8건을 기록했습니다. DeepSeek 호출은 6회, 총 56,916토큰입니다. 첫 시도는 모델 계획이 모두 무효하여 `partial`로 끝났고, 제한된 재시도를 추가한 후 다시 실행해 완료했습니다.

두 대학의 배포 점검은 공개 페이지 13개와 정적 자산·역할 등을 확인했고, 읽기 전용 IDOR 재현도 성공했습니다. 이 기록은 세 실습 대상의 개별 실행 결과이며 전체 취약점 탐지 성능을 뜻하지 않습니다. `xss-parser`가 필요한 XSS 브라우저 실행 확인은 보류 상태입니다.

기존 단일 게시판 실습 프로필은 `stored_xss_canary`입니다. Alice 세션 준비 GET 후 `xss-parser`가 Chromium으로 게시판 한 페이지의 입력 폼, `POST /api/posts`와 HTML 렌더링 위치를 변경 없이 관찰합니다. `casper-db`는 관찰한 API 입력 위치를 SQLite의 과거 XSS 사례와 대조해 참고 판정을 반환합니다. `pentest-db`는 `cases.json`의 초안 XSS 정보를 입력 위치·브라우저 확인 방법에 대한 조언으로 반환합니다. 과거 일치나 카탈로그만으로 현재 취약점을 확정하지 않습니다.

Agent가 실행별 고유 마커를 가진 무해한 canary를 만들고 DeepSeek가 단일 `{method,url,body}` POST를 제안합니다. 모델 출력은 코어가 만든 허용 요청과 정확히 같아야 합니다. 로컬 gateway가 게시판 원점·canary 본문·순서를 확인하고 `guardrail`이 요청 예산과 범위를 전송 직전에 평가합니다. 그 뒤 `attack-module`이 `POST /api/posts`를 한 번 실행합니다. 별도 Chromium 브라우저가 생성된 같은 게시글을 다시 열어 고유 마커의 콜백이 실제 호출됐는지 확인합니다. 코어의 결정론적 `reflect()`는 게시글 ID·마커·원점·표시·콜백·오류와 증거 참조를 확인해 finding을 판정합니다. `pentest-db`는 이벤트·보고서를 `reports/pentest-db-runs/`에 저장합니다. 모델 요청은 실패 시 기본 1회, 설정에 따라 최대 2회 재시도할 수 있지만 검사 POST는 자동 재시도하지 않습니다. `npm start`만으로는 모델 호출이나 검증이 시작되지 않습니다.

기존 교차 사용자 삭제 검사(`agent_cross_user_delete_canary`)는 명시적으로 선택하는 레거시 프로필입니다. 대시보드에서 `vul-web-1`의 **저장형 XSS 검사 시작**은 저장형 XSS 프로필을 사용합니다. 코어 fixture는 모의 응답을 사용하며 입력 URL에 접속하지 않습니다.

모의 응답 지연은 fixture 모드에서 0.9초·1.8초·3초로 선택하며 다음 실행에 적용됩니다. 이는 실제 대상이나 모델의 응답 시간 측정값이 아닙니다. 배경 애니메이션과 reduced-motion 설정, 이벤트 검색, JSON 복사, 모바일 화면과 Ctrl/Cmd+K URL 입력을 지원합니다.

일시정지는 지원하지 않습니다. 코어의 gateway timeout은 기본 10초이며, Chromium parser와 `casper-db` 조회에는 더 긴 제한을 적용합니다.

## 실행 범위

기존 fixture와 단일 검사는 `agent/src/orchestrator.js`의 `runOnce()` 또는 고정 IDOR 런타임을 사용합니다. 범용 점검은 별도 `runGeneralAssessment()`에서 가변 반복과 여러 가설·검사를 처리합니다. 범용 Agent loop는 실제 수신한 관측·계획·정책·실행·검증 단계와 반복 번호를 표시하며, 미관측 단계나 전체 취약점 완료율을 추정하지 않습니다. Live activity 아래 결과 패널은 실행 중에 안전한 가설·검사·증거 메타데이터와 잠정 판정을 보여주고, 최종 보고서가 저장된 뒤 다중 finding·근거·미점검 사유를 보여줍니다. 기존 고정 모듈 지도는 단일 검사에만 적용합니다.

| 모드 | Agent 판단 | 읽기·과거 자료 | HTTP 요청·정책 | 실행 기록 |
| --- | --- | --- | --- | --- |
| 코어 fixture | `RuleReasoningEngine` | `xss-parser`·`casper-db` 고정 응답 | `attack-module`·`guardrail` 고정 응답 | `pentest-db` 인메모리 테스트 대역 |
| 기존 단일 게시판 실습 | `DeepSeekReasoningEngine` 또는 규칙 엔진 | 실제 Chromium parser와 SQLite 매칭 | 실제 curl과 규칙 평가기 | 초안 카탈로그 조회·로컬 JSON 파일 저장 |
| 기존 대학 IDOR 실습 | 고정 규칙 | 정해진 레코드·역할 응답 | 등록된 실습 원점의 읽기 비교 | 중앙 실행 이력·JSON |
| 범용 점검 | 실제 DeepSeek 모델과 `runGeneralAssessment()` | 공개·고정 계정 읽기 관측, 소스·의존성·과거 자료 요약 | 등록·관측 경로 GET, 허용된 소스 읽기, 격리 게시판 삭제 canary, 대학의 고정 IDOR 비교 | 다중 finding·증거·모델 메타데이터를 중앙 이력·JSON에 저장 |

기존 게시판 XSS 실습의 대상은 서버가 만든 소유 게시판으로 고정됩니다. `xss-parser`의 첫 읽기 전용 관찰은 후보를 찾고, POST 후 별도 브라우저 관찰은 같은 canary의 실행 증거를 수집합니다. 해당 실행의 finding은 저장형 XSS 판정에 한정됩니다. 범용 점검은 세 등록 대상에서만 실행하며 임의 URL은 허용하지 않습니다. 모델이 제안한 취약점 종류는 제한하지 않지만 현재 독립 확정기는 게시판의 새 글 교차 사용자 삭제 대조와 대학의 고정 역할 읽기 비교를 지원합니다. 게시판 도구는 Bob의 새 글이 그대로 남는 Alice의 권한 없는 삭제 요청을 먼저 확인한 뒤에만 후보 요청을 보냅니다. 다른 유형의 후보는 관측과 근거를 남기되 취약점으로 확정하지 않습니다. `xss-fuzzer`는 통합 제외 범위를 유지합니다.

사용자가 중지한 세션의 실행 상태는 `stopped`이며, 코어가 중단 때문에 생성한 보고서는 기존 계약의 `failed` 상태를 유지합니다. 최종 저장 응답을 허용해 중단 보고서도 관측할 수 있게 합니다.

## 연결과 기록 보관

현재 실행은 서버가 관리합니다. 브라우저 새로고침 후 SSE가 재연결되면 서버의 현재 실행을 다시 표시하고, 서버에서 진행 중인 루프는 계속됩니다. 연결이 끊기면 화면에 연결 상태를 표시하며 재연결을 시도합니다. 연결이 끊긴 동안의 화면 상태를 완료로 판단하지 마세요.

현재 실행과 보고서는 로컬 중앙 실행 저장소에 기록되어 서버 재시작 후 실행 이력에서 다시 열 수 있습니다. 브라우저의 `localStorage`에는 화면 설정과 중앙 이력 연결 전의 최근 실행 기록만 보관됩니다. 기존 단일 게시판 실습에서 `pentest-db` 어댑터는 이벤트와 최종 보고서를 `reports/pentest-db-runs/`의 로컬 JSON 파일에도 저장합니다. 범용 점검의 전체 결과는 중앙 저장소의 JSON 아티팩트로 보존하며, 확정된 finding의 HWPX는 결과 화면에서 각각 내려받습니다. 미재현·판정 불가·미점검 결과는 JSON과 화면에서 확인합니다.

```powershell
npm run check

npm run test:general-ui
```

`test:general-ui`는 `xss-parser`를 가져오지 않고 범용 결과의 정규화·HTML 이스케이프, 실제 브라우저 렌더링과 범용 실행 요청을 검증합니다. API·워커의 별도 집중 테스트는 요청부터 실제 범용 런타임, 중앙 저장과 재조회까지 가짜 모델로 검증합니다. 범용 시작에는 설정된 실제 DeepSeek 모델이 필요하며 기존 XSS/IDOR 단일 검사도 선택할 수 있습니다. 가변 단계는 고정 완료율로 표시하지 않고 미점검 항목을 별도로 보여줍니다.

검증 범위는 engine fixture와 기록 직렬화, 코어의 단일 반복·요청/응답 관측·중단 처리, 서버 API와 SSE, loopback 제한, 실제 모듈 어댑터와 정적 파일 응답입니다. 로컬 XSS 통합 테스트는 임시 게시판에서 관찰 → DB 참고 조회 → 제한된 POST → 독립 브라우저 실행 증거 → finding·보고서까지 확인합니다. 잘못된 마커·게시글·순서·요청 범위를 거부하는 테스트도 포함합니다. DeepSeek 요청은 가짜 클라이언트로 대체해 비용 없이 검사하며, 브라우저 테스트에는 Playwright Chromium 설치가 필요합니다. 브라우저에서는 두 시작 경로, 진행·중지, 새로고침 후 현재 실행 복원, Agent I/O, 이력과 JSON 내보내기를 확인합니다.

앱 내 브라우저에서는 JSON 내보내기의 파일 저장 완료를 확인하지 못했습니다. 최종 다운로드는 Chrome 또는 Edge에서 확인하세요.
