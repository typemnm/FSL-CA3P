# CA3P Security Workspace — 로컬 통합 대시보드

`DESIGN.md`의 검정 배경, 민트·제이드 별빛과 주변광을 적용한 로컬 대시보드입니다. 자산에서 등록 대학 또는 외부 URL을 먼저 파싱해 URL별 결과를 확인하고, 판단 엔진을 골라 점검을 시작합니다. 등록 대학은 규칙 엔진이나 DeepSeek, 외부 URL은 지원되는 DeepSeek 모델을 사용합니다. 이전 fixture·단일 검사 기록은 실행 이력에서 조회·비교하고 JSON으로 내보낼 수 있습니다.

## 실행

대시보드 서버만 실행하려면 Node.js 24가 필요합니다. 등록 실습과 외부 URL의 범용 점검은 실제 DeepSeek 설정이 필요합니다. AI 채팅에서 지원하는 로컬 LLM 설정과 범용 점검의 모델 지원은 별개입니다. 범용 점검에는 PATH에서 실행할 수 있는 `curl`, Python 3.11 이상과 `casper-db`의 의존성도 필요합니다. 설치 명령은 [루트 README](../README.md)에 있습니다. 프로젝트 루트에서 실행합니다.

```powershell
npm start
```

또는 대시보드 디렉터리에서 직접 실행할 수 있습니다.

```powershell
cd agent-dashboard
npm run dev
```

브라우저에서 <http://127.0.0.1:4173>을 엽니다. 서버는 `127.0.0.1`에만 바인딩합니다. 터미널에서 `Ctrl+C`로 종료합니다. 루트 시작 명령에 `npm start -- --port 4174`를 사용하거나 대시보드에서 `$env:PORT = '4174'`를 설정한 뒤 실행하면 포트를 변경할 수 있습니다.

## 사용 방법

1. **자산**에서 **vul-web2 실습 대상** 또는 **외부 URL**을 선택합니다. 실습 대상은 대한대학교·원창대학교를 고르면 서버가 설정한 시작 URL이 채워지고, 외부 대상은 URL을 직접 입력합니다. **파싱하기**를 누르면 같은 원점에서 발견된 페이지 경로를 한 번에 수집합니다. 등록 대학은 최대 48페이지·50초, 외부 URL은 최대 8페이지·28초입니다. 부분 수집 시 원인을 표시하고 해당하는 경우 미수집 후보 수를 표시합니다.
2. 수집된 URL 목록에서 경로를 하나씩 선택해 HTTP 상태, 제목, 기술·라이브러리, 폼, 발견 경로, 수집 오류를 확인합니다. 결과는 15분간 임시 보관됩니다. 시작 URL을 바꾸거나 결과가 만료되면 다시 파싱해야 합니다.
3. 파싱한 URL이 하나 이상 성공하면 **판단 엔진 선택**이 표시됩니다. 등록 대학은 규칙 엔진 또는 사용 가능한 DeepSeek 모델을 고르고 **진단하기**를 누릅니다. 외부 URL은 외부 범용 점검을 지원하는 DeepSeek 모델을 고릅니다. DeepSeek 사용에는 `agent/.env` 또는 프로세스 환경변수의 `DEEPSEEK_API_KEY`가 필요하고 API 비용이 발생할 수 있습니다. 외부 URL의 사전 점검은 진단하기를 누를 때 서버에서 수행합니다. 범위 정책과 독립 검증기가 지원하는 검사만 실행하며 미지원 검사는 미점검으로 기록합니다.
4. **공격** 화면의 상태 줄에서 서버가 보고한 실행 상태와 수신 이벤트 수를 확인합니다. **실행 중지**로 중단을 요청할 수 있습니다. Trace inspector의 **실행 이벤트** 선택창에서 요청·응답·Agent I/O를 확인하고, **보고서**와 **실행 이력**에서 저장된 결과를 열거나 JSON으로 내보냅니다.
5. **모델 변경 시 실험 초기화 확인** 토글을 켜면 모델을 바꿀 때 흔적 제거 여부를 묻습니다. **예**는 초기화 완료 후 모델을 바꾸고, **아니오**는 흔적을 유지합니다. 수동 **실험 초기화**도 사용할 수 있습니다.

외부 URL 결과의 Web Parser 기술·라이브러리 단서는 허용된 HTTP 응답의 헤더·HTML·스크립트 URL 문자열을 분석한 것입니다. 외부 URL은 브라우저 DOM, JavaScript 실행 후 상태와 폼을 수집하지 않습니다. 목록에 없다는 것이 해당 기술을 사용하지 않는다는 뜻은 아닙니다. 등록 대학의 프리뷰는 브라우저 관찰을 사용합니다.

진단이 시작되면 수집한 URL별 결과 전체가 실행에 묶이고 실행 기록과 보고서에 저장됩니다. DeepSeek 범용 진단은 그 URL별 관찰 요약을 초기 AI 입력으로 받습니다. 기존 고정 IDOR 규칙 엔진은 파싱 결과를 판정 입력으로 사용하지 않습니다. 상세 초기화 범위는 [실험 초기화 안내](../docs/EXPERIMENT_RESET.md)에 있습니다.

범용 모델 요청의 기본 최대 출력은 2,048토큰입니다. `DEEPSEEK_MAX_TOKENS`를 명시하면 그 값을 우선 사용합니다.

범용 점검은 HTTP/인증 읽기 관측, 허용된 저장소 소스·의존성, 이전 실행과 `casper-db`의 사례·공격 정보 요약을 출처와 함께 모델에 제공합니다. 모델은 유형을 미리 지정받지 않고 여러 가설을 제안하지만, 실행은 등록된 대상·경로·요청 예산으로 제한됩니다. 대학 대상에서는 알려진 레코드의 역할별 읽기를 비교할 수 있습니다. 확인 가능한 근거가 없는 가설은 `inconclusive` 또는 `not_tested`로 남깁니다. 범용 경로에는 브라우저 실행을 확인하는 도구가 없으므로 브라우저 실행 증거가 필요한 XSS는 확정하지 않습니다. 범용 다중 결과는 실행 이력과 JSON에 저장하고, 최종 `confirmed` finding마다 HWPX 초안을 한 개씩 작성합니다. 다른 상태에는 HWPX를 작성하지 않습니다.

### 로컬 실측 기록

같은 날 대한대학교 `4101` 범용 실행은 6회 반복·26개 가설·23개 검사로 완료됐습니다. `/api/admissions/partner/applications/:id`에서 접근 제어 1건을 독립 확인했고, 판정 불가 14건·미점검 11건을 기록했습니다. DeepSeek 호출은 6회, 총 64,087토큰입니다.

원창대학교 `4102` 범용 실행은 6회 반복·23개 가설·22개 검사로 완료됐습니다. `/api/staff/mobile/cases/:id`에서 접근 제어 1건을 독립 확인했고, 판정 불가 14건·미점검 8건을 기록했습니다. DeepSeek 호출은 6회, 총 56,916토큰입니다. 첫 시도는 모델 계획이 모두 무효하여 `partial`로 끝났고, 제한된 재시도를 추가한 후 다시 실행해 완료했습니다.

두 대학의 배포 점검은 공개 페이지 13개와 정적 자산·역할 등을 확인했고, 읽기 전용 IDOR 재현도 성공했습니다. 이 기록은 두 대학 실습 대상의 개별 실행 결과이며 전체 취약점 탐지 성능을 뜻하지 않습니다. 범용 경로에는 XSS 브라우저 실행 확인이 없습니다.

### 폐기된 단일 검사와 기록 호환성

기존 단일 검사는 폐기됐습니다. 여기에는 코어 fixture, 게시판 저장형 XSS `stored_xss_canary`, 교차 사용자 삭제 `agent_cross_user_delete_canary`가 포함됩니다. 서버는 이 모드와 프로필의 새 실행 요청을 거부합니다. 저장된 실행은 원래의 모드와 출처를 유지해 실행 이력과 보고서에서 표시합니다.

현재 화면은 배경 애니메이션과 reduced-motion 설정, 이벤트 선택, JSON 복사와 모바일 화면을 지원합니다. 모의 응답 지연 설정은 제거했습니다. Ctrl/Cmd+K는 자산의 대상 입력으로 이동합니다.

일시정지는 지원하지 않습니다.

## 실행 범위

대학에서 규칙 엔진을 고르면 기존 고정 IDOR 런타임(`local-lab-rule`)을 사용합니다. DeepSeek를 고르면 `runGeneralAssessment()`의 가변 반복과 여러 가설·검사를 사용합니다. 상태 줄은 서버 상태와 실제 수신 이벤트 수를 표시합니다. 단계·반복 번호·입출력은 선택한 이벤트에서 확인하고, 최종 finding·근거·미점검 사유는 보고서에서 확인합니다.

| 모드 | Agent 판단 | 읽기·과거 자료 | HTTP 요청·정책 | 실행 기록 |
| --- | --- | --- | --- | --- |
| 기존 대학 IDOR 실습 (호환성·테스트) | 고정 규칙 | 정해진 레코드·역할 응답 | 등록된 실습 원점의 읽기 비교 | 중앙 실행 이력·JSON |
| 범용 점검 | 실제 DeepSeek 모델과 `runGeneralAssessment()` | 공개·고정 계정 읽기 관측, 소스·의존성·과거 자료 요약 | 등록·관측 경로 GET, 허용된 소스 읽기, 격리 게시판 삭제 canary, 대학의 고정 IDOR 비교 | 다중 finding·증거·모델 메타데이터를 중앙 이력·JSON에 저장 |
| 외부 URL 범용 점검 | `external-general` 모드의 범용 루프 | 비인증 공개 자료와 이전 실행의 근거 | 사전 점검한 동일 원점·허용 경로의 정책 제한 요청과 독립 검증 | 다중 finding·증거·모델 메타데이터를 중앙 이력·JSON에 저장 |

이 화면에서 새로 시작할 수 있는 등록 실습의 범용 점검은 두 대학 대상입니다. 외부 URL도 `external-general` 모드로 범용 반복 점검을 실행하며, 사전 점검으로 고정한 원점·경로와 요청 예산을 따릅니다. 모델이 제안한 취약점 종류는 제한하지 않지만 독립 검증기가 지원하고 증거로 확인된 후보만 확정합니다. 기존 `external-read-only` 실행 기록은 공개 페이지 관찰 보고서로 계속 표시합니다. `xss-fuzzer`는 통합 제외 범위를 유지합니다.

사용자가 중지한 세션의 실행 상태는 `stopped`이며, 코어가 중단 때문에 생성한 보고서는 기존 계약의 `failed` 상태를 유지합니다. 최종 저장 응답을 허용해 중단 보고서도 관측할 수 있게 합니다.

## 연결과 기록 보관

현재 실행은 서버가 관리합니다. 브라우저 새로고침 후 SSE가 재연결되면 서버의 현재 실행을 다시 표시하고, 서버에서 진행 중인 점검은 계속됩니다. 연결이 끊기면 화면에 연결 상태를 표시하며 재연결을 시도합니다. 연결이 끊긴 동안의 화면 상태를 완료로 판단하지 마세요.

현재 실행과 보고서는 로컬 중앙 실행 저장소에 기록되어 서버 재시작 후 실행 이력에서 다시 열 수 있습니다. 브라우저의 `localStorage`에는 화면 설정과 중앙 이력 연결 전의 최근 실행 기록만 보관됩니다. 범용 점검의 전체 결과는 중앙 저장소의 JSON 아티팩트로 보존하며, 확정된 finding의 HWPX는 결과 화면에서 각각 내려받습니다. 미재현·판정 불가·미점검 결과는 JSON과 화면에서 확인합니다.

## 검증

대시보드 디렉터리에서 다음 명령을 사용합니다.

```powershell
npm run check
npm test
npm run test:general-ui
```

`test:general-ui`는 범용 결과의 정규화·HTML 이스케이프, 실제 브라우저 렌더링과 범용 실행 요청을 검증합니다. API·워커의 별도 집중 테스트는 요청부터 실제 범용 런타임, 중앙 저장과 재조회까지 가짜 모델로 검증합니다. 등록 실습의 범용 시작에는 설정된 실제 DeepSeek 모델이 필요합니다. 모의 코어·단일 검사 시작 UI와 Agent loop 그래프가 없고, 다중 이벤트 선택·실행 중지·기존 기록 조회가 유지되는지 검사합니다. 가변 단계는 고정 완료율로 표시하지 않고 미점검 항목을 별도로 보여줍니다.

검증 범위는 engine fixture와 기록 직렬화, 서버 API와 SSE, loopback 제한, 실제 모듈 어댑터와 정적 파일 응답입니다. 저장형 XSS 실행 확인 어댑터(`observeStoredXssExecution`)는 실제 Chromium으로 이 실행의 게시글·마커만 확정하는지 별도로 검증합니다. 이 어댑터를 호출하는 실행 경로는 없습니다. DeepSeek 요청은 가짜 클라이언트로 대체해 비용 없이 검사하며, 브라우저 테스트에는 `web-parser`의 Playwright Chromium 설치가 필요합니다. 브라우저에서는 등록 실습과 외부 URL의 파싱 결과를 확인하고 범용 점검을 시작하는 경로, 상태·중지, 새로고침 후 현재 실행 복원, 이벤트별 Agent I/O, 이력과 JSON 내보내기를 확인합니다.

앱 내 브라우저에서는 JSON 내보내기의 파일 저장 완료를 확인하지 못했습니다. 최종 다운로드는 Chrome 또는 Edge에서 확인하세요.
