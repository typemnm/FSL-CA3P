# 취약한 바닐라 JS 게시판

저장형 XSS와 삭제 요청의 파라미터 변조를 재현하는 **로컬 보안 실습용** 게시판입니다. 프런트엔드는 바닐라 JavaScript로 작성했고, 서버는 외부 패키지 없이 Node.js 내장 모듈만 사용합니다. 공개 서버에 배포하거나 실제 사용자 데이터를 입력하지 마세요.

## 실행

Node.js 18 이상이 필요합니다.

```powershell
cd D:\whs\과제\vul-web-1
npm start
```

브라우저에서 <http://127.0.0.1:3000>에 접속합니다. 기본 실행 주소는 로컬 컴퓨터의 `127.0.0.1:3000`입니다. 테스트는 프로젝트 폴더에서 `npm test`로 실행합니다.

게시글은 `data/posts.json`에 저장됩니다. 초기 게시글로 돌아가려면 서버를 중지하고 이 파일을 삭제한 뒤 다시 실행하세요. 서버가 시작할 때 파일이 없으면 관리자 글을 포함한 초기 데이터를 생성합니다.

## 계정과 게시판

처음 접속하면 `alice` 사용자 정보가 서명된 `board_user` 쿠키로 설정됩니다. 화면에서 `alice`와 `bob` 계정을 전환할 수 있습니다. `admin`은 초기 게시글의 작성자로만 제공되며 화면에서 선택할 수 없습니다. 사용자는 글을 작성하고 상세 내용을 볼 수 있습니다.

## 취약점 재현

반드시 이 로컬 실습 서버에서만 진행하세요.

### 1. 저장형 XSS

1. `alice`로 새 글 쓰기 패널에 임의의 제목을 입력합니다.
2. 본문에 다음 값을 입력해 게시합니다.

   ```html
   <img src=x onerror=alert(1)>
   ```

3. 작성한 게시글이 목록에 나타날 때 브라우저에서 `alert(1)`이 실행됩니다.

원인은 서버가 입력된 본문을 그대로 저장하고, 프런트엔드가 게시글 본문을 HTML로 렌더링하기 때문입니다. 따라서 본문에 들어간 이벤트 핸들러가 브라우저에서 실행됩니다.

### 2. 파라미터 변조로 관리자 글 삭제

`alice`로 접속한 상태에서 브라우저 개발자 도구의 Console을 엽니다. 먼저 `GET /api/posts` 결과에서 관리자 글의 ID를 확인합니다.

```js
const { posts } = await (await fetch('/api/posts')).json();
console.log(posts.filter(post => post.authorId === 'admin').map(post => ({ id: post.id, title: post.title })));
```

초기 데이터가 유지된 상태라면 관리자 글 중 하나의 ID가 `1`입니다. 다음 요청은 `alice`의 쿠키로 전송되지만 관리자 글을 삭제합니다.

```js
await (await fetch('/api/posts/1?authorId=admin', { method: 'DELETE' })).json();
```

성공하면 `{ ok: true, deletedId: 1 }`이 반환되고 목록에서도 해당 글이 사라집니다. 이미 삭제했거나 초기 데이터를 변경했다면 위에서 확인한 다른 관리자 글 ID로 경로의 `1`을 바꾸세요.

원인은 삭제 API가 서명된 `board_user` 쿠키의 실제 사용자 ID와 게시글 작성자를 비교하지 않고, 클라이언트가 자유롭게 바꿀 수 있는 `authorId` 요청 파라미터를 권한 판단에 사용하기 때문입니다. 쿠키 서명 자체가 이 삭제 권한 검사를 대신하지는 못합니다.
