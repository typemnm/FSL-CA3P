# 대한대학교·원창대학교 웹사이트 사전 침해분석 및 취약점 보고서

- **문서 상태:** 대한대학교 Express와 원창대학교 Spring Boot 전환본의 코드·자동 HTTP smoke·컨테이너 검증 범위를 구분해 기록 · 전체 침투시험 미실시
- **분석 기준일:** 2026-10-20
- **대상:** 대한대학교·원창대학교 웹사이트의 로컬 격리 실행본
- **분류 기준:** [OWASP Top 10:2025](https://top10.owasp.org/2025/)

## 1. 분석 범위와 증거 상태

두 대학은 본 프로젝트를 위해 만든 **가상의 기관**이다. 이 문서는 대한대학교의 `src/server.mjs`·`src/db.mjs`, 원창대학교의 `wonchang/src/main/java/edu/wonchang/portal/` 및 Thymeleaf 템플릿, 각각의 의존성 선언·Docker 설정을 검토하고, `npm run smoke`로 두 사이트의 일부 HTTP 동작을 확인하는 **사전 침해분석 보고서**다. 대한대학교의 협력기관 입학 접수 조회와 원창대학교의 교직원 모바일 업무 조회도 범위에 포함한다. smoke 검증은 대한대학교의 메모리 DB와 원창대학교의 폐기 가능한 임시 컨테이너·SQLite DB에서 수행되며, 실제 침해사고·외부 노출·지속 DB의 피해를 뜻하지 않는다. 표에서 `재현`은 해당 자동 시험에서 확인한 현상만을 가리킨다. 나머지 항목은 코드상 근거가 있더라도 악용 가능성·영향 범위를 아직 확정하지 않았다.

검증 환경은 `localhost` 또는 격리된 사설 네트워크로 한정한다. 학생·교직원·협력기관·관리자 계정, 공지, 일정, 연구성과, 입학 자료는 모두 더미 데이터여야 하며 실제 개인정보, 실제 대학의 계정·콘텐츠·상표·연락처를 가져오지 않는다. 부속 업무 데이터의 연락처는 `example.invalid` 도메인을 사용한다. 공격 재현은 승인된 이 환경과 테스트 계정에서만 수행한다. 공개 배포나 외부 접근이 필요하면 의도된 결함을 제거한 별도 빌드를 사용한다.

아래에 적은 경로·메서드·필드명은 현재 소스 코드 기준이다. `미검증`은 해당 위험 자체를 HTTP로 재현하지 않았음을 뜻한다. 대한대학교의 `package-lock.json`과 원창대학교의 Maven 선언을 확인했지만 전체 전이 의존성 감사, 장기 세션 영향, A09의 운영 로그·경보 검증은 아직 수행하지 않았다. Spring 전환본의 Docker 기동·두 컨테이너 `healthy` 상태와 배포 읽기 검사를 확인했다. 컨테이너에 대한 장기 운영 검증은 수행하지 않았다.

## 2. 서비스 모델과 참조 정보구조

두 사이트는 독립된 기관명, 교표, 색상, 입학·학사 콘텐츠를 가진 대학 포털로 구성한다. [국립창원대학교 공식 홈페이지](https://www.changwon.ac.kr/kor/main.do)의 상위 정보구조인 **대학안내, 입학안내, 대학·대학원, 학사안내, 연구·산학, 대학생활, 대학홍보**와 공지·학사일정·통합검색 같은 이용 흐름을 참고한다. 해당 사이트의 디자인, 문구, 자료 또는 신뢰 표지를 그대로 복제한다는 뜻은 아니다. 실제 대학 사이트처럼 자연스러운 메뉴, 서로 연결되는 여러 페이지, 일관된 게시판·검색·로그인·관리 기능을 갖추되 두 가상 대학의 정체성과 콘텐츠는 독자적으로 작성한다.

| 영역 | 구현된 정상 기능 | 보안상 경계 |
| --- | --- | --- |
| 공개 포털 | 홈, 대학소개, 학과·연구, 입학, 학사일정, 대학생활, 공지 목록·상세·검색 | 공개 데이터 조회와 관리자 수정 권한 분리 |
| 계정 | 로그인·로그아웃, 일반 사용자와 관리자 구분 | 인증, 세션, 비밀번호 저장·시도 횟수 |
| 부속 업무 | 대한대학교 협력기관 입학 접수 조회, 원창대학교 교직원 모바일 업무 조회 | 역할 검사와 별개의 개별 건 소유권 검증, 반복 조회 탐지 |

| 운영 | 오류 화면, 로그, 경보, 패키지 관리 | 예외 처리, 사고 추적, 외부 의존성 |

## 3. 외부 의존성 검토

대한대학교와 원창대학교는 **서로 다른 런타임과 직접 의존성 집합**을 사용한다. 대한대학교 이미지는 루트 `package-lock.json`으로 `npm ci`를 수행하고, 원창대학교 이미지는 `wonchang/pom.xml`로 Spring Boot JAR을 빌드한다. `compose.yaml`은 별도 이미지·컨테이너·브리지 네트워크·데이터 볼륨을 선언하며 호스트 포트를 각각 `127.0.0.1:4101`, `127.0.0.1:4102`에만 게시한다. 대한대학교 DB는 Node.js 내장 `node:sqlite`, 원창대학교 DB는 SQLite JDBC를 사용한다. 전체 전이 의존성 감사는 미실시이며, 패키지 버전만으로 애플리케이션에서의 악용 가능성이 입증되지는 않는다.

| 사이트 | 구성요소와 버전 | 구현된 용도와 확인할 위험 |
| --- | --- | --- |
| 대한대학교 | `express@4.21.2` · `nunjucks@3.2.4` · `cookie-parser@1.4.7` · `dayjs@1.11.13` · `lodash@4.17.15` | HTTP 라우팅, 서버 렌더링, 쿠키 파싱, 날짜 표시, 관리자 설정. `POST /admin/settings`는 JSON의 `path`를 `lodash.set(settings, path, value)`에 전달한다. 관리자 세션의 시험 입력으로 해당 프로세스의 `Object.prototype`에 속성이 추가됐다. [GHSA-p6mc-m468-83gw](https://github.com/advisories/GHSA-p6mc-m468-83gw). |
| 원창대학교 | `spring-boot-starter-webmvc` · `spring-boot-starter-thymeleaf` · `sqlite-jdbc@3.53.4.0` · `gson` · `commons-text@1.9` (Spring Boot 4.1.1 · Java 17) | HTTP 처리·서버 렌더링·DB·JSON·관리자 설정. `POST /admin/settings`의 문자열 값에 `StringSubstitutor.createInterpolator()`를 적용한다. 사용자 제어 입력을 검증하지 않고 보간하는 경우에 관한 [Apache 보안 안내](https://commons.apache.org/proper/commons-text/security.html)를 참조한다. |

직접 외부 의존성은 대한대학교 **5개**, 원창대학교 **5개**이고 패키지 생태계가 분리돼 있다. `scripts/smoke.mjs`는 선언된 직접 의존성 개수와 Express·Spring 프레임워크 구분을 단언한다. Maven과 npm의 전이 의존성 전체 감사를 마쳤다는 뜻은 아니다.

## 4. OWASP Top 10:2025별 사전 분석

**판정 상태:** Spring 전환본의 자동 시험은 A01의 무인증 삭제·민원 IDOR·부속 업무 건별 IDOR, A02의 공개 진단 경로, A03의 대한대학교 프로토타입 오염과 원창대학교 설정값 보간, A04의 동일한 솔트 없는 SHA-1 해시, A05의 검색 조건 변경, A06·A10의 대표 공지 삭제 후 홈 500, A07의 연속 실패 시도, A08의 서명 없는 일정 반영을 대상으로 한다. 서로 다른 언어의 예외 표현과 A03 동작은 구분한다. **A09는 정적 코드 검토만 하며**, A03·A07 등의 추가 후속 피해와 운영 환경 영향은 미검증이다. 심각도는 격리된 더미 데이터 환경의 우선순위 추정이며 최종 결과에 따라 조정한다.

| 분류 · 예상 심각도 | 코드 경로 | 재현 결과와 영향 범위 | 권고 수정 |

| [A01:2025 접근 통제 실패](https://top10.owasp.org/2025/A01_2025-Broken_Access_Control/) · 높음 | `POST /admin/posts/:id/delete`에는 관리자 권한 검사가 없고 ID만으로 글을 삭제한다. `GET /api/mypage/requests/:id`는 로그인만 확인하고 민원 소유자를 확인하지 않는다. 대한대학교 `/admissions/partner`·`/api/admissions/partner/applications/:id`와 원창대학교 `/staff/mobile`·`/api/staff/mobile/cases/:id`는 역할을 확인하지만 숫자 ID의 상세 건 소유자는 확인하지 않는다. | **재현:** 두 대학 모두 비로그인 게시글 삭제가 302이고 학생1에서 학생2의 민원 조회가 200이었다. 부속 업무는 비로그인 302·학생 역할 403·담당자 본인 목록 범위 제한을 확인했지만, 담당자1로 다른 담당자 건의 상세 화면과 API를 조회하면 모두 200이었다. | 삭제 요청에 관리자 권한을 적용한다. 민원·부속 업무 조회에는 세션 사용자별 건 소유권 또는 정당한 관리 권한을 조회 조건에 포함하고, 허용되지 않은 건은 노출하지 않는다. |

[lodash GHSA-p6mc-m468-83gw](https://github.com/advisories/GHSA-p6mc-m468-83gw), [Apache Commons Text 보안 안내](https://commons.apache.org/proper/commons-text/security.html). | **재현:** 대한대학교에서는 `__proto__.labProbe`로 프로토타입 오염을 확인했다. 원창대학교에서는 무해한 환경변수 참조를 설정값에 입력해 보간 결과가 임시 SQLite DB에 저장됨을 확인했다. 두 동작은 서로 다른 유형이며 원창대학교에서 JavaScript 프로토타입 오염을 주장하지 않는다. 코드 실행·외부 통신은 검증하지 않았다. | 두 패키지를 패치 버전으로 올리고 허용된 설정 경로·값만 처리한다. 원창대학교는 사용자 입력을 범용 보간기에 넘기지 않는다. |
| [A04:2025 암호화 실패](https://top10.owasp.org/2025/A04_2025-Cryptographic_Failures/) · 높음 | 대한대학교 `src/db.mjs`와 원창대학교 `Store.java`가 비밀번호를 솔트 없이 SHA-1으로 해시하고 `POST /login`에서 같은 해시로 비교한다. | **재현:** 두 대학의 더미 계정 `student1`·`student2`에서 같은 초기 비밀번호가 동일한 40자리 16진수 해시로 저장됐다. DB 유출 시 비밀번호 추측 비용이 낮다. | Argon2id 또는 적절히 설정한 scrypt/bcrypt의 개별 솔트 해시로 바꾸고 초기 암호를 재발급한다. |
| [A05:2025 인젝션](https://top10.owasp.org/2025/A05_2025-Injection/) · 높음 | `GET /notices?q=`, `GET /news?q=`, `GET /api/search?q=`가 검색어를 `LIKE` 조건의 SQL 문자열에 직접 결합한다. | **재현:** 두 대학 모두 `/api/search`에서 무결과 대조 검색과 비교해 `q=' OR 1=1 --` 입력이 다수 결과를 반환했다. 게시판 검색 경로와 데이터 추출 범위는 미검증이다. | 바인딩 매개변수와 허용된 정렬·필터 목록을 사용하고 입력 오류를 일관되게 처리한다. |
| [A06:2025 불안전한 설계](https://top10.owasp.org/2025/A06_2025-Insecure_Design/) · 높음 | `featured_post_id` 초기값은 `1`이고, 관리자 글 삭제는 이 설정을 갱신하지 않는다. 대표 글 삭제를 허용하는 관리 기능과 홈의 필수 데이터 전제가 충돌한다. | **재현:** 두 대학 모두 `id=1` 삭제 뒤 공개 홈이 500이었다. 자동 시험은 무인증 요청으로 같은 삭제 경로를 호출했다. 관리자 UI에서 삭제하는 동선은 별도 검증 필요하다. | 삭제 전 대체 대표 공지를 지정하거나, 빈 상태를 정상 화면으로 렌더링하고 데이터 불변식을 강제한다. |
| [A07:2025 인증 실패](https://top10.owasp.org/2025/A07_2025-Authentication_Failures/) · 높음 | 두 서비스가 고정 초기 관리자 계정을 만들고 `POST /login`에는 실패 횟수 제한이 없다. 두 서비스 모두 세션 토큰을 `Math.random()`으로 만들며 만료 검사도 없다. | **부분 재현:** 두 대학에서 관리자 계정에 잘못된 비밀번호를 8회 연속 제출했고 모두 401이었다. 429 또는 잠금은 발생하지 않았다. 장기 세션·토큰 추측의 실효성은 미검증이다. | 설치 시 임의 초기 비밀번호 발급·최초 로그인 변경, 시도 제한, 암호학적 난수 기반 세션·만료·안전한 쿠키를 적용한다. |

## 5. 중점 시나리오: 정상 관리 기능이 홈 장애로 이어지는 경로

이 시나리오는 **권한 없는 삭제(A01)**와 **권한 있는 관리자의 정상 삭제 후에도 남는 장애(A06·A10)**를 구분한다. 자동 시험은 전자를 사용해 500까지 재현했다. 관리자 화면에도 같은 삭제 경로를 호출하는 버튼이 있으므로 정상 관리자 삭제가 동일한 데이터 상태를 만들 수 있지만, 그 화면 동선은 따로 실행 검증하지 않았다.

| 단계 | 코드와 자동 시험에서 확인한 사실 | 남은 확인 사항 |
| --- | --- | --- |
| 1. 초기 상태 | 두 사이트에서 초기 `GET /`이 200이며, 설정의 `featured_post_id`는 `1`이다. | 대표 공지와 DB 행의 캡처를 보관한다. |
| 2. 삭제 | 비로그인 `POST /admin/posts/1/delete`가 두 사이트에서 302를 반환한다. 삭제 핸들러는 대표 공지 설정을 갱신하지 않는다. | 관리자 UI에서 같은 버튼을 누른 결과와 삭제 전후 DB 상태를 별도 기록한다. |
| 3. 장애 발생 | 이어진 `GET /`이 두 사이트에서 500을 반환했다. 홈 서버 코드가 조회 결과 검사 없이 대표 공지의 제목을 읽는다. | 전체 오류 응답과 서버 로그를 증거로 보관한다. |
| 4. 영향 범위 | 삭제 전 13개 공개 경로가 정상이었음은 확인했다. | 삭제 **후** 공지·입학·학사 등 하위 페이지 가용성을 확인한다. |
| 5. 복구 | 삭제 데이터를 되돌리거나 유효한 대표 공지를 재지정하면 정상화할 수 있는 구조다. | 실제 복구 절차·시간·재발 조건을 시험한다. |

**확인된 원인 경로:** 설정이 `id=1`을 계속 가리키는 동안 해당 공지를 삭제하면 조회 결과가 없고, 조회 결과의 제목 접근이 예외를 만든다. 삭제 자체는 게시물 관리 기능이지만, 대표 공지의 생명주기와 홈 가용성을 함께 설계하지 않아 서비스 장애로 이어진다. 접근 통제를 고쳐도 이 상태 처리 결함은 남는다.

## 6. 자동 검증 결과와 남은 증거

`npm run smoke`는 `scripts/smoke.mjs`에서 대한대학교를 **메모리 DB와 임시 루프백 포트**, 원창대학교 Spring Boot를 **새로 빌드한 임시 이미지·컨테이너·SQLite 파일 DB와 Docker가 할당한 임시 루프백 포트**에서 실행해 통과했다. 시험 후 원창대학교 임시 컨테이너를 제거했으며 Compose의 지속 DB는 변경하지 않았다. 자동 시험은 각 사이트의 직접 외부 의존성이 4개 이상이고 Express·Spring이 분리된 점도 단언했다. 별도로 `docker compose up --build -d wonchang`으로 Spring 전환본을 기동해 두 서비스가 `healthy`인 상태를 확인하고, `node scripts/deployment-check.mjs`로 읽기 기능을 점검했다. 원창대학교 SQLite 파일의 체크섬은 Spring 전환 직전과 첫 정상 기동 직후 동일했다. 초기 배포 검사에는 게시글 상세 GET에 따른 조회수 증가가 있었고, 수정된 검사는 게시글 링크만 확인하며 실행 전후 체크섬이 동일했다. 아래 OWASP 결과는 **주로 격리된 smoke의 자동 단언 범위**를 뜻하며, Compose의 지속 컨테이너에서 모든 취약점을 재현했다는 뜻은 아니다. 전체 요청·응답 원문, 시각, DB 전후 자료와 보안 이벤트 기록은 별도 보관하지 않았으며 후속 시험에서 확보한다. 대한대학교의 프로토타입 시험 속성은 검증 직후 삭제했다. 민감한 쿠키와 비밀번호는 증거에서 가린다.

Spring 전환본의 첫 Compose 기동에서는 `/tmp`가 `noexec`로 마운트돼 SQLite JDBC가 그곳에 추출한 네이티브 라이브러리를 로드하지 못했다. 원창대학교 Dockerfile에서 대상 아키텍처의 `libsqlitejdbc.so`를 빌드 중 `/app/native`로 복사하고 `JAVA_TOOL_OPTIONS`에 해당 라이브러리 경로를 지정했다. 수정 후 재기동에서는 두 컨테이너의 `healthy` 상태, 원창대학교 SQLite 파일의 전환 직전·첫 정상 기동 직후 동일한 체크섬, 배포 읽기 검사 통과를 확인했다. 이 장애는 애플리케이션의 의도된 취약점 재현 결과와 별개의 배포 설정 문제다.

| 확인 항목 | 대한대학교 | 원창대학교 | 남은 검증·증거 |
| --- | --- | --- | --- |

## 7. ARTEX 금융권 사건을 참고한 부속 업무 시나리오

### 공개 자료에서 확인되는 범위

[CrowdStrike의 2026년 10월 7일 분석](https://www.crowdstrike.com/en-us/blog/unknown-threat-actor-uses-artex-to-target-south-korean-finance/)에 따르면 2026년 9월 말부터 10월 초까지 한국 금융권을 겨냥한 침해 활동과 데이터 유출이 있었고, 공격자 측 공개 디렉터리에서 ARTEX 설정과 Claude Code 세션 등이 발견됐다. 해당 분석은 대출모집인용 진행조회와 직원 모바일 업무지원 시스템이 침해됐다는 업계 보도를 인용한다. 공격자의 실명·소속과 전체 피해 기관 수는 확정하지 않았으며, 중국어 사용자이자 금전 목적이라는 평가는 *중간 신뢰도*로 제시했다.

[금융위원회의 2026년 10월 14일 발표](https://www.fsc.go.kr/po010101/87927)는 신한은행 사고 전후 다수 금융회사에서 확인된 침해를 설명하면서 **동일 공격자 여부와 AI 활용 여부는 조사 중**이라고 밝혔다. 따라서 금융권에서 보고된 모든 침해를 한 ARTEX 운영자의 결과로 합산하지 않는다. 공개 자료는 최초 진입에 쓰인 정확한 취약점이나 ARTEX가 IDOR를 발견했다는 사실도 확정하지 않는다.

| 가상 서비스 경로 | `/admissions/partner`, `/api/admissions/partner/applications/:id` | `/staff/mobile`, `/api/staff/mobile/cases/:id` |
| 정상 경계 | `partner` 역할의 담당자에게 자신의 지원 건만 목록으로 표시 | `staff` 역할의 담당자에게 자신의 업무 건만 목록으로 표시 |
| 모의 결함 | 숫자 조회번호의 상세 화면·API에서 `partner_user_id` 소유권을 검사하지 않음 | 숫자 관리번호의 상세 화면·API에서 `staff_user_id` 소유권을 검사하지 않음 |
| 노출되는 데이터 | 가상 지원자 이름·전형·진행 상태·`example.invalid` 연락처 | 가상 학생 이름·학번·업무 메모·`example.invalid` 연락처 |

평가에서는 담당자 계정을 이미 사용할 수 있다는 **가정** 아래 자신의 목록을 확인한 뒤 다른 담당자의 번호를 조회한다. 두 대학 모두 역할 검사는 작동하지만 객체별 인가가 빠져 있다. 자동 시험은 소수의 연속 번호 조회가 200을 반환하고 제한되지 않는 점을 확인했다. 대규모 유출, IP 교체, 침투 자동화, 실제 ARTEX 실행은 구현하거나 검증하지 않았다. 이 가정은 실제 금융권 사고의 구체 침입 수법에 대한 주장이 아니다.

부속 서비스는 공개 대학 사이트의 입학안내·대학생활 메뉴에서 자연스럽게 연결되지만 로그인해야 접근할 수 있다. 대한대학교 `src/db.mjs`와 원창대학교 `Store.java`의 멱등 시드가 각 DB에 가상 담당자와 기록을 추가하며, 두 서비스의 이미지·직접 의존성·볼륨·네트워크는 계속 분리된다. 발견 후 수정 우선순위는 **건별 소유권 확인**, 반복 조회 제한과 감사 이벤트, 협력기관·교직원 역할별 최소 권한이다.

## 8. 개선 우선순위

1. **즉시:** 삭제 API 권한·기관 경계와 부속 업무 건별 소유권 확인, 기본 관리자 자격 증명 제거, 검색 쿼리 매개변수화, 대표 공지 삭제 후 홈의 빈 상태 처리.
2. **다음:** 비밀번호 해시 교체, 대한대학교의 `lodash`와 원창대학교의 `commons-text` 업데이트 및 사용 위치 검토, 가져오기 데이터 검증.
3. **운영 전:** 디버그 응답 제거, 반복 조회·삭제·로그인 실패·권한 거부 이벤트 로깅과 경보, 두 대학의 주요 메뉴 회귀 확인.
