# 대한대학교·원창대학교 웹사이트 사전 침해분석 및 취약점 보고서

- **분석 기준일:** 2026-10-20
- **대상:** 로컬 Docker Compose에서 분리 실행하는 두 가상 대학 포털
- **분류 기준:** [OWASP Top 10:2025](https://top10.owasp.org/2025/)
- **증거 범위:** 현재 소스·의존성 선언 검토와 격리된 데이터베이스의 HTTP 기능 검사

## 1. 요약과 판정 기준

대한대학교와 원창대학교는 서로 다른 기술 스택으로 운영되는 가상 대학 포털이다. 대학안내, 입학, 학사, 연구, 대학생활, 공지·대학소식·일정·검색을 제공한다. 학생 문의와 관리자 게시글·일정 관리 외에 대한대학교는 입학 협력기관 조회, 원창대학교는 교직원 모바일 업무 조회를 제공한다. 계정, 지원자, 연락처와 게시물은 평가용 가상 데이터다.

각 사이트의 **직접 외부 의존성 세 가지가 서로 다른 CVE의 영향 버전에 해당**한다. 해당 버전의 포함과 웹사이트에서 실제 공격 결과가 발생한다는 판단은 별개다. 이 보고서는 버전, 취약 API 호출 경로, 필요한 권한, 확인한 현상과 미검증 영향을 분리한다. CVE 세 건씩은 평가 대상으로 선정한 목록이며 모든 전이 의존성의 취약점 목록을 뜻하지 않는다.

**코드상 확인**은 현재 소스에 경로가 있음을, **재현**은 격리된 자동 검사에서 응답 또는 데이터 상태를 확인했음을 뜻한다. **미검증**은 버전 또는 호출 경로를 확인했더라도 CVE가 설명하는 최종 피해를 실행으로 입증하지 않았다는 뜻이다. 의도된 결함이 있으므로 두 컨테이너는 `127.0.0.1`에만 게시하고 실제 개인정보를 사용하지 않는다.

## 2. 서비스 구성과 정상 기능

| 구분 | 대한대학교 | 원창대학교 |
| --- | --- | --- |
| 서버·화면 | Node.js 24 이상, Express 4.21.2, Nunjucks 3.2.4 | Java 17, Spring Boot 4.1.1, Spring MVC, Thymeleaf |
| 데이터 저장 | Node.js 내장 `node:sqlite`, `daehan-data` 볼륨 | SQLite JDBC, `wonchang-data` 볼륨 |
| 컨테이너·접속 | `daehan`, `127.0.0.1:4101` | `wonchang`, `127.0.0.1:4102` |
| 특화 업무 | 협력기관 입학 접수 목록·상세 조회 | 교직원 모바일 업무 목록·상세 조회 |

두 사이트는 별도 이미지, 컨테이너, 브리지 네트워크와 데이터 볼륨을 사용한다. 공개 포털은 `/`, `/about`, `/admissions`, `/colleges`, `/academics`, `/research`, `/campus`, `/facilities`, `/notices`, `/news`, `/schedule`, `/faq`와 게시글 상세 화면으로 구성된다. 국립창원대학교의 상위 메뉴와 공지·학사일정·통합검색 흐름을 정보구조 참고 대상으로 삼았으며, 사이트 이름과 콘텐츠는 가상으로 작성했다.

| 영역 | 구현된 기능 | 주요 경로 |
| --- | --- | --- |
| 검색·콘텐츠 | 게시판 검색·페이지 이동, 전체 검색, 게시글 상세 | `/notices`, `/news`, `/api/search`, `/notices/:id`, `/news/:id` |
| 계정·학생 | 로그인·로그아웃, 마이페이지, 문의 작성·조회 | `/login`, `/logout`, `/mypage`, `/mypage/requests` |
| 관리자 | 공지·대학소식 작성·수정·삭제, 일정 가져오기, 사이트 설정 | `/admin`, `/admin/posts`, `/admin/import`, `/admin/settings` |
| 대한 부속 업무 | 담당자별 입학 접수 목록·상세 | `/admissions/partner`, `/api/admissions/partner/applications/:id` |
| 원창 부속 업무 | 담당자별 모바일 업무 목록·상세, YAML 일정 원고·TAR 자료 묶음 미리보기 | `/staff/mobile`, `/api/staff/mobile/cases/:id`, `/admin/schedule/preview`, `/admin/archive/preview` |

대한대학교는 JSON5 형식의 전체 검색 필터(`filters`)와 Markdown 게시글 본문 렌더링을 제공한다. 원창대학교는 관리자 일정 원고를 YAML로, 자료 묶음을 TAR로 미리보기한다. 두 미리보기는 게시된 콘텐츠를 변경하지 않으며 관리자 역할이 필요하다.

## 3. 외부 의존성 및 CVE 평가

대한대학교의 직접 의존성은 `express@4.21.2`, `nunjucks@3.2.4`, `cookie-parser@1.4.7`, `dayjs@1.11.13`, `lodash@4.17.15`, `json5@2.2.1`, `markdown-it@12.3.1`이다. `package-lock.json`이 설치 버전을 고정한다. 원창대학교는 Spring Boot Web MVC·Thymeleaf 스타터, `sqlite-jdbc@3.53.4.0`, Gson, `commons-text@1.9`, `snakeyaml@1.33`, `commons-compress@1.23.0`을 Maven에서 선언한다. 두 사이트의 직접 의존성 집합은 겹치지 않는다.

## 5. 중점 시나리오: 게시글 삭제와 사이트 가용성

두 사이트의 관리자 화면은 공지 삭제 기능을 제공한다. 그러나 삭제 요청 경로 자체에는 관리자 권한 검사가 없다. 설정의 `featured_post_id`가 대표 공지 `id=1`을 가리키는 상태에서 이 글이 삭제되면 홈은 해당 행이 존재한다고 가정해 `title`을 읽는다. 빈 조회 결과 때문에 `GET /`에서 500 오류가 발생한다.

여기에는 **권한 없는 삭제(A01)**와 **권한 있는 관리자의 삭제 이후에도 남는 설계·예외 처리 결함(A06·A10)**이 함께 존재한다. 삭제 권한 검사만 고쳐도 유효한 대표 공지가 없는 상태를 홈에서 처리해야 한다. 복구 경로는 삭제된 행을 되돌리거나 유효한 대표 공지를 지정하는 것이지만, 자동 복구·복구 시간과 다른 페이지의 상태는 별도 검증 대상이다.

## 6. ARTEX 사건을 참고한 부속 업무 위험

[CrowdStrike의 2026년 10월 7일 분석](https://www.crowdstrike.com/en-us/blog/unknown-threat-actor-uses-artex-to-target-south-korean-finance/)은 2026년 9월 말~10월 초 한국 금융권을 겨냥한 침해 활동을 설명하며, 공격자 측 공개 디렉터리에서 ARTEX 설정과 LLM 세션을 확인했다고 밝혔다. 해당 분석은 업계 보도를 인용해 대출모집인용 진행조회와 직원 모바일 업무지원 시스템의 침해를 소개한다. [금융위원회의 발표](https://www.fsc.go.kr/po010101/87927)는 여러 금융회사 침해의 동일 공격자 여부와 AI 사용 여부가 조사 중이라고 설명한다. 공개 자료만으로 실제 사건의 최초 진입 취약점이나 ARTEX가 IDOR를 발견했다는 결론을 내릴 수 없다.

이 프로젝트는 그 **업무 유형**을 대학 포털의 부속 서비스로 구현한다. 대한대학교 `partner1`과 `partner2`는 본인 입학 접수 목록만 보지만 `/admissions/partner?id=` 및 `/api/admissions/partner/applications/:id`의 상세 조회에는 `partner_user_id` 조건이 없다. 원창대학교 `staff1`과 `staff2`도 본인 업무 목록만 보지만 `/staff/mobile?id=` 및 `/api/staff/mobile/cases/:id`에 `staff_user_id` 조건이 없다. 로그인과 역할 확인은 작동하더라도 담당자 간 객체 인가가 빠진 **별도의 모의 IDOR**다. 연락처는 `example.invalid`를 사용하며 실제 금융권 시스템의 URL이나 개인정보를 사용하지 않는다. 대량 수집과 실제 ARTEX 실행은 검증 범위에 없다.

## 7. 검증 상태와 한계

소스와 의존성 선언에서 두 사이트의 기능·OWASP 경로 및 선정 CVE 세 건씩의 호출 위치를 확인했다. `npm run smoke`는 대한대학교를 메모리 DB·임시 포트에서, 원창대학교를 임시 이미지·컨테이너·SQLite DB에서 실행해 **두 사이트 모두 통과**했다. `docker compose up --build -d` 뒤 두 컨테이너는 `healthy`였고, `node scripts/deployment-check.mjs`도 통과했다. 배포 검사를 포함한 재기동 확인 구간에서 두 지속 DB의 SHA-256 체크섬은 각각 동일했다.

| 범위 | 확인한 결과 | 한계 |
| --- | --- | --- |
| 정상 기능 | 두 사이트의 공개 13개 경로·정적 자산, 게시판 상세·검색·페이지 이동, 로그인·로그아웃, 학생 문의, 역할 제한, 관리자 글 작성·수정·일정 가져오기가 통과했다. | 브라우저별 화면 품질과 장기 운영은 시험하지 않았다. |
| A01·A02 | 두 사이트에서 비로그인 게시글 삭제는 302, 타 학생 문의 상세는 200, 무인증 진단은 200이었다. 부속 업무에서는 비로그인 302·학생 403, 다른 담당자 건의 상세 화면·API 200이었다. | 대량 연속 조회와 실제 개인정보 노출은 범위 밖이다. |
| A03·A04·A05 | 대한의 `lodash.set` 무해 프로토타입 오염, JSON5 상속 필터, Markdown 굵은 글씨 렌더를 확인했다. 원창의 Commons Text 환경값 보간, YAML·TAR 정상 미리보기를 확인했다. 두 사이트의 동일 비밀번호 SHA-1 해시와 검색 SQL 조건 변경도 확인했다. | CVE에 따른 코드 실행, 외부 연결, 장시간 CPU 점유는 시험하지 않았다. |
| A06·A07·A08·A10 | 두 사이트에서 대표 공지 삭제 후 홈 500, 관리자 비밀번호 8회 실패에 제한 응답 없음, 서명 없는 일정 JSON 반영을 확인했다. | 관리자 UI를 통한 대표 공지 삭제 동선과 복구 시간은 확인하지 않았다. |
| A09 | 보안 감사 이벤트·경보는 정적 코드 검토로만 평가했다. | 실제 운영 로그 수집기나 경보 시스템은 시험하지 않았다. |
| 의존성·배포 | 대한의 `package-lock.json`에 선정 npm 버전 세 건이 고정돼 있다. 원창 실행 JAR에 `commons-text-1.9.jar`, `snakeyaml-1.33.jar`, `commons-compress-1.23.0.jar`가 포함돼 있다. 두 컨테이너 배포 읽기 검사가 통과했다. | 전체 Maven·npm 전이 의존성 감사는 하지 않았다. |

`GET /notices/:id`와 `GET /news/:id`는 조회수를 DB에 증가시킨다. 쓰기·삭제·장문 부하 재현은 지속 볼륨 대신 임시 DB에서 수행했다. 배포 검사는 게시글 상세 GET을 생략해 지속 DB의 조회수도 늘리지 않았다. 이 보고서의 CVE 선정은 전체 소프트웨어 구성 분석을 대체하지 않으며, Java 실행 환경과 다른 전이 의존성은 추가 판정이 필요하다.

## 8. 개선 우선순위

1. 게시글 삭제에 관리자 권한을 적용하고, 학생 문의와 두 부속 업무의 상세 조회 SQL에 객체 소유권 조건을 포함한다. 대표 공지가 없어도 홈이 정상 화면을 반환하도록 한다.
2. 검색 SQL을 바인딩 매개변수로 바꾸고, 공개 진단 경로와 오류 스택 노출을 제거한다. 초기 관리자 암호, SHA-1 저장, 로그인 제한 및 세션 생성·만료를 개선한다.
3. 의존성을 각 권고의 수정 버전 이상으로 올리고 위험한 사용 경로를 제거한다. `lodash.set` 경로 허용 목록, JSON5 파싱 결과의 자체 속성 검사, Markdown 입력 길이·렌더 시간 제한, Commons Text 보간 입력 제한, SnakeYAML 안전 생성자·타입 제한, TAR PAX 헤더 검증과 처리 시간 제한을 적용한다.
4. 일정 가져오기에 출처·서명·스키마 검증과 트랜잭션을 적용하고, 로그인 실패·권한 거부·삭제·반복 상세 조회의 구조화 감사 이벤트와 경보를 마련한다.
